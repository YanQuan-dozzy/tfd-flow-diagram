# 布局套路与走线技巧

## 零、先选布局方向

教材范例（材料仓库的入库/发料/月底结账）一律是**纵向**：一条主干从上往下，岗位挂在左右。

```
        采购员            ← col 0（主干）
          ↓
        入库单            ← 单据夹在两次处理之间
          ↓
订货单文件 → 复核 ← 库工   ← 台账/岗位侧挂 col -1 / col +1
          ↓
      合法入库单
          ↓
     材料入库验收 ← 库工
          ↓        ↘
       入库文件     交库单 → 采购员（走最外侧回流）
```

什么时候用横向（一条主线一个 `row`）：多条业务主线并行、彼此有交叉引用时，例如"借书"和"还书"两条线要共用"读者信息表"。横向能把这些共用节点摆在同一列。

选型口诀：**单线程走纵向，多线程走横向。**

## 一、把业务翻译成网格

```
col →   0        1          2           3        4
row 0  读者 → 查看库存 → 借阅图书 → 借书信息单 → 借出处理 → 图书借阅表
row 1            注册账号 → 账号申请单
row 2  读者共用列 ·······  读者信息表 ← 图书管理员
row 3  查看记录 → 借阅处理 → 借书信息单 → 归还图书 → 还书信息单
```

三条规则足够撑起绝大多数 TFD：

1. **一条主线 = 一个 row**，按时间顺序从左往右排；主线内部每一步 +1 col。
2. **同一参与者只画一次**，放在它第一次出现的 col，用竖线连到其他 row。读者/库工/会计这类"贯穿角色"就是靠列复用撑起整张图。
3. **单据插在两个处理之间**（`doc`），**台账挂在处理旁边**（`store`）——台账不参与主线推进，放在处理正下方、正上方或侧边一格。

列数控制在 4–8，行数 3–6。超了就拆成两张图（教材也是这么做的：入库一张、出库一张、月底结账一张）。

## 二、先画骨架，再补细节

1. 先只放 `unit` 和 `proc`，把主干走通、看上图是否顺；
2. 再把 `doc` 插进两次处理之间；
3. 最后挂 `store` 和"管理员/台账"这类支线。

一次性写完 25 个节点容易出重叠，分两步改反而快。

## 三、走线

默认什么都不用指定，脚本按下面的顺序判断：

| 两个节点的关系 | 自动选边 |
|---|---|
| 同一行、右侧 | 右 → 左，水平直连 |
| 同一列、下方 | 下 → 上，垂直直连 |
| 其他 | 按 dx/dy 谁大选边，然后 L 形或 Z 形折 |

补充机制（都是自动的，不用管）：

- **端点吸附**：两个锚点相差 < 6px 时拉成一条直线，消掉"几像素的小台阶"。
- **落点分散**：同一节点同一侧有 2 条以上箭头时，自动排成 0.33 / 0.67 / 0.25·0.5·0.75，不会叠在一个点上。
- **避让择优**：选定网格后，每条线在"朝向目标的出入边组合 × 7 档平行车道偏移"里择优，代价排序——
  穿框 1000 > 出线方向错 900 > 收线方向错 800 > 交叉 500 > 共线重合 420 > 同侧进出 300 >
  逆向出线 260 > 偏离人工指定 70 > 折角 8/个 > 长度 0.03/px。
  之后还有定向修复轮：只重排仍冲突的线，直到清零。
- **禁止 U 形**：同侧进、同侧出（绕一个 U 回到同一个框）直接从候选里剔除。
- **车道偏移**：竖/横走线可以在 ±22/44/66px 的平行车道间挪动，用来错开已有线条。
- **拥挤自适应**：同一侧挂了两条以上线时，节点自动放大到 92×48，列间距自动加到 64；图里有块状箭头时列间距加到 110（块箭头要横着走进节点，得留出跑道）。因此两个箭头不会挤在同一条线上。
- **读写成对**：`a→b` 与 `b→a` 同时存在时，落点自动错到 0.35 / 0.65，画成一上一下两条平行箭头（范例里"更新库存文件 ⇅ 库存文件"就是这个样子）。
- **store 右边**：开口侧允许进出（范例就是从开口侧进），只是加了一点代价，能让开就让开。
- **画布包围盒**：按"节点 + 全部拐点"计算，绕行的线不会被裁掉。

什么时候才手工介入：

- 自动走线横穿了半个画布 → 加 `bend` 把折点拉近目标；
- 两条线严重并行难分辨 → 改 `fromSide` 或 `at0`/`at1` 错开；
- 必须绕开一片区域 → `route: "poly"` + `via: [[x,y]]` 手打点（先算好坐标，别凭感觉）。

优化器跑完仍剩冲突时（布局太挤、没有可用的出入边），说明该调 `col/row` 或加大 `hgap`/`vgap`，而不是继续拧走线参数。

## 四、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 两个框叠在一起 | 两个节点用了同一个 `col,row` | 改行或改列；脚本会报"节点重叠" |
| 文字被挤出框外 | 标签太长、`max_node_w` 太大 | 缩短标签（"打印并邮寄账单"→"打印账单"），或调小 `max_w` 让它折行 |
| 折行断在词中间 | 框太窄，只能按字数硬切 | 别用 `maxw` 硬压宽度；折行会自动断在"并/及"之前 |
| 主干断成两截 | 漏了中间的单据节点 | 补 `doc`，单据本身就是"交接" |
| 箭头右进右出很别扭 | 目标在源的左下方，却给了 `toSide: right` | 删掉显式边，让脚本自动选 |
| 两条线粘成一条 | 两个箭头共用一个节点的同一侧、落点又相同 | 优化器会避开；仍出现就调 `at0`/`at1` 或换 `col` |
| 回流线被形状挡住 | 回流线跟其他节点挤在同一列 | 给回流线单独一列（`col: -2`），让它可以一路直上 |
| 两条回流线互相压住 | 都从同一侧进、落点又是同高 | 外层线的 `at1` 取大（靠下）、内层线取小（靠上），两条才不会交叉 |
| 连线旁边冒出小字 | 照着旧示例写了 `edge.label`，或想标注"是/否""留底" | **不允许**。渲染器已删除该能力，label 会被丢弃并告警；语义要靠单据/处理节点表达 |
| 图上多出标题或图例 | 打开了 `show_title` / `legend` | 关闭它们，图名写进回复正文第一行 |
| 块状箭头头部被压扁 | 收尾直线段比箭头还短 | 用 `bend` 把拐点挪远，给头部留出 ≥ 30px 的直线段 |
| 单据画成了 `proc` | 标签写成了"填写入库单" | 标签改"入库单"，动作另起一个 `proc` |
| 图太长被裁 | 行数太多 | 拆图，或把 `hgap`/`vgap` 调小到 28/44 |
| 纵向图主干拐了弯 | 主干节点换了 `col` | 主干固定 `col: 0`，侧挂才用 ±1 |
| 读写没有方向感 | 只画了一条箭头 | 补一条反向箭头，脚本会自动错开 |

## 五、交付自检清单

- [ ] 主干从左到右一口气能读完，没有回头箭头打结
- [ ] 每个 `unit` 只出现一次；每条主线首尾都落在真实角色上
- [ ] `doc` 都在主线中间，`store` 都在处理旁边
- [ ] 没有标签溢出、没有框体重叠、没有箭头穿框
- [ ] 图里只有图形本身，没有标题/副标题/图例；图名请在回复正文里写
- [ ] 打印成黑白仍能读懂（不靠颜色区分语义）
